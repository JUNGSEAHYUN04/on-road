# On-Road (온로드, 가제)

보육원 아동·청소년 및 자립준비청년을 위한 **AI 진로·자립 성장 코치**

정책 정보를 찾고, 쉬운 말로 이해하고, 신청을 준비하고, 생활을 계획하는 과정을 하나의 흐름으로 연결하는 서비스입니다.

## 배경

보호종료를 앞두거나 이미 보호가 종료된 자립준비청년은 주거·교육·취업·생활비 등 다양한 지원정보를 직접 찾아야 합니다. 관련 제도와 정보가 여러 기관에 분산되어 있어 필요한 정보를 찾고 이해하는 과정이 복잡합니다.

On-Road는 이러한 문제를 해결하기 위해, 정형 데이터(정책 조건 필터링)와 AI(검색·설명·요약)를 역할을 나누어 활용합니다. AI가 자격 여부를 임의로 판단하지 않고, 사용자가 확인해야 할 조건과 선택지를 안내하는 것을 원칙으로 합니다.



## 핵심 기능

### 1. 정책 검색 (RAG) — 메인 기술 기여
- 정책 데이터 15~20개 기반 실제 DB로 구축 (SQLite/JSON 아님, 원문 그대로 보존)
- 사용자 프로필(연령/지역) 1차 필터링 + RAG 검색 결합 (하이브리드 검색)
- 근거 문서 기반 답변 생성, hallucination 방지 로직 포함
- (여유되면) 멀티턴 후속 질문 지원

### 2. 쉬운 말 변환 — 서브 기술 기여
- 정책 원문 → 이해하기 쉬운 문장으로 변환
- 핵심조건(대상/금액/기간/신청방법) 누락 없이 검증

### 3. 생활비 배분 시뮬레이션
- 소득/지원금 입력 → 항목별 배분 → 부족 항목 판정
- 부족 항목 대안 배분 시나리오 자동 제안
- 부족 항목과 관련 정책 연결 (1번 기능 재사용)

### 4. 신청 준비 체크리스트
- 정책검색 결과 기반 → 신청 준비 단계 자동 생성
- 흐름: 정책 찾기 → 쉬운말 이해 → 체크리스트 준비 → (필요시) 시뮬레이션



## 추가 기능 (여유 시, 담당자 미정)

### 5. 정책 비교
- 검색 결과 중 2~3개 정책을 조건/금액/기간 기준으로 표 비교
- 1번(정책 검색) 결과 재사용, 프론트 UI 위주(백엔드 조회 API 1개 필요)

### 6. 다음 행동 추천
- 진행 중인 체크리스트, 미완료 항목, 저장한 정책 기반으로 다음 행동을 규칙 기반으로 제안
- AI 없이 조건문으로 구현

### 7. 성장 기록 (간단 버전)
- 저장한 정책, 완료한 체크리스트, 시뮬레이션 결과를 모아 보여주는 마이페이지
- 새 로직 없이 기존 데이터 조회 위주

## 팀 구성 및 역할

| 역할 | 담당 업무 |
|---|---|
| RAG & AI | 정책 검색 RAG 파이프라인, hallucination 방지 로직, 쉬운말 변환 프롬프트 설계, 체크리스트 단계 설명 생성(보조) |
| 백엔드 / DB | DB 스키마 구축(정책·사용자 테이블) + 벡터 검색 설정, 조건 필터링(연령/지역) 로직, 시뮬레이션 룰 로직, 체크리스트 상태 저장 API, 전체 API 설계 |
| 프론트엔드 | 온보딩/대시보드 UI, 정책검색 UI, 시뮬레이션 UI, 체크리스트 UI, 배포·통합 |
| 데이터 / 기획 및 평가 | 정책 데이터 수집·정제, 쉬운말 검증 스크립트, 시뮬레이션 기준표 산정, 테스트 질문셋 작성, 정량 지표 측정 |

핵심 기능(1~4번) 완료 후 여유가 있으면 정책 비교(5번, 프론트 위주) → 다음 행동 추천(6번, 백엔드 룰 로직 + 프론트 UI) → 성장 기록(7번, 백엔드 조회 API + 프론트 UI) 순으로 담당자 간 추가 배분.



## DB 결정 사항

- **DB**: 처음부터 실제 DB로 구축 (SQLite/JSON 임시 방안 대신 확정), 종류는 백엔드 담당자가 정해서 `docs/db-schema.md`에 명시
- **벡터 검색**: DB 종류에 맞춰 통합 처리 또는 별도 벡터DB 연동 여부는 백엔드 담당자가 결정
- **초기 데이터**: 데이터 담당자가 만든 `data/policies/policies.json`을 DB 테이블에 삽입하는 시드 스크립트를 백엔드 담당자가 작성



## 브랜치 전략

- `main`: 데모 발표 직전 최종 안정 버전
- `develop`: 통합 브랜치, 각 feature 브랜치는 여기로 먼저 merge → 통합 테스트 후 체크포인트 시점에 맞춰 main으로 merge
- `feature/rag-search`, `feature/easy-text`: RAG & AI
- `feature/db-schema`, `feature/simulation-logic`, `feature/checklist-api`: 백엔드
- `feature/onboarding-ui`, `feature/search-ui`, `feature/simulation-ui`, `feature/checklist-ui`: 프론트엔드
- `feature/data`, `feature/eval-scripts`: 데이터/평가
- `feature/policy-compare`, `feature/next-action`, `feature/growth-record`: 추가 기능(5~7번), 여유 시 진행

PR 생성 시 설명란에 "작업 내용 + 테스트 결과(수치 있으면 포함)"를 기록합니다. 막힌 부분은 회의 대신 이슈로 등록합니다. 체크포인트 회의는 1주차 끝/2주차 끝/3주차 중반, 총 3번만 진행합니다.



## 정량 지표

- RAG hallucination 발생률
- RAG 답변 정확도
- 쉬운말 변환 핵심조건 누락률
- 원문 대비 변환문 문장길이 감소율



## 스코프 아웃 (데모 제외)

- 나를 알아보기 & 미래 탐색 (관심사 탐색, 직업 탐색, 미래 생활 탐색, 진로·학습 로드맵)
- 자립생활 실행·훈련 일부 (자립 준비 체크리스트, 자가점검, 실천 과제, 상담 요청 정리)
- 정책정보 관리자 기능 (등록·수정·비활성화, 검수 관리, 관리자 권한)

- 회원정보 수정/삭제



## 개발 기간

3주 (1차 발표/데모 기준)
